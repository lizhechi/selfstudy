> 项目：AI Learning Project  
> 模块：M0 — Markdown 与技术文本基础

> - `Roadmap_v0.1.md`
>
> 性质：模块级教学规格  
> 作用：定义 M0 的学习目标、范围、教学方式、必做练习、完成判据与收尾要求。  
> 本文件不得覆盖或修改 Anchor / Roadmap 中的长期原则。

---

## 1. 模块定位

M0 是 AI Learning Project 的基础工具模块。

目标不是“精通 Markdown”，而是建立后续所有：

- 技术笔记；
- Prompt / Task Specification；
- 问题树；
- ADR；
- README；
- 实验记录；
- Evaluation 方案；
- Agent 任务说明；
- ProjectVox 文档；

所需要的基础技术文本表达能力。

M0 应尽量短而扎实，完成后应立即进入 M1，而不是无限扩展为独立的 Markdown 专项课程。

---

## 2. 学习目标

完成 M0 后，学习者应能够独立完成结构清晰、可读、可维护的 Markdown 技术文档。

重点能力包括：

1. 正确使用 Markdown 常用语法；
2. 用标题和列表表达信息层级；
3. 用代码块、引用、表格等形式表达不同类型的信息；
4. 理解 Markdown 文档在 Git 中的差异比较方式；
5. 能重构结构混乱的技术文本；
6. 初步理解“适合人类阅读”和“适合 AI 读取”的 Markdown 结构有何共同点；
7. 能为后续 AI 学习项目自行编写简单的技术文档。

---

## 3. 前置要求

无 Markdown 前置知识要求。

默认学习者具备：

- 基础 Windows 文件操作能力；
- 能使用文本编辑器；
- 已接触最基础的 Git 操作，或正在 ProjectVox 中同步学习 Git。

M0 不要求：

- HTML 基础；
- CSS；
- 静态网站生成器；
- 高级 Mermaid；
- 文档自动化工具链。

---

## 4. 必须掌握的内容

### 4.1 文本与段落基础

- 普通段落；
- 空行；
- 换行；
- Markdown 源文本与渲染结果的区别。

### 4.2 标题

- `#`
- `##`
- `###`
- 合理的标题层级；
- 避免跳级和滥用标题。

目标：

> 学会用标题表达信息结构，而不是只把标题当作“放大字体”。

### 4.3 强调

- `**加粗**`
- `*斜体*`
- 适度使用强调；
- 避免整段加粗导致层级失效。

### 4.4 列表

- 无序列表；
- 有序列表；
- 嵌套列表；
- checklist；
- 列表与段落的关系。

### 4.5 代码

- 行内代码；
- fenced code block；
- 语言标识；
- 代码与解释文本的边界。

### 4.6 引用

- `>`
- 多段引用；
- 引用与普通说明的区别；
- 技术文档中引用块的适用场景。

### 4.7 链接

- 普通链接；
- 相对路径；
- 文档间链接；
- 链接文本的可读性。

### 4.8 表格

- 基础表格；
- 对齐；
- 表格适用场景；
- 什么时候不应该使用表格。

### 4.9 分隔线

- `---`
- 使用分隔线划分较大区域；
- 避免用大量分隔线替代真正的信息结构。

### 4.10 转义与常见陷阱

- Markdown 特殊字符；
- 反斜杠转义；
- 代码中包含 Markdown 字符；
- 嵌套结构导致的渲染问题。

---

## 5. 应有所涉猎的内容

以下内容不要求在 M0 深入掌握：

- GitHub Flavored Markdown；
- Mermaid；
- Markdown lint；
- HTML 嵌入；
- README 常见结构；
- 文档目录；
- 相对路径设计；
- 面向 AI 的结构化 Markdown；
- 技术文档中的 front matter 概念。

目标仅为建立认知，为后续模块按需深入。

---

## 6. 教学方式

M0 应遵循：

> 讲解 → 小练习 → 独立输出 → Review → 修正 → 综合作业

每个新语法不应只通过“看示例”学习。

应尽快要求学习者亲自输入、修改和解释。

### 6.1 避免机械背诵

不要求学习者背诵所有语法。

重点是：

- 会用；
- 知道什么时候用；
- 看见陌生 Markdown 时能大致读懂；
- 忘记细节时知道如何快速查证。

### 6.2 强调结构而非装饰

教学重点应持续提醒：

Markdown 的主要价值不是美化文本，而是表达：

- 信息层级；
- 语义边界；
- 代码与正文区别；
- 任务结构；
- 文档关系。

### 6.3 与 Git 结合

如果条件允许，应让学习者：

1. 新建 `.md` 文件；
2. 修改内容；
3. 使用 `git diff` 查看变化；
4. 理解 Markdown 源文本在版本控制中的优势；
5. 完成一次简单提交。

但 Git 不是 M0 的主要教学目标。

## 7. 必做练习

### Exercise 1 — 基础语法

创建一份 Markdown 文件，必须包含：

- 一级标题；
- 二级标题；
- 普通段落；
- 加粗；
- 行内代码；
- 无序列表；
- 有序列表；
- 代码块；
- 引用；
- 链接；
- 分隔线。

目标：

> 确认基础语法可独立使用。

---

### Exercise 2 — 技术笔记

撰写一份短技术笔记。

主题可以来自：

- Git；
- AI；
- ProjectVox；
- 当前正在学习的其他技术主题。

要求：

- 标题层级清晰；
- 不依赖大段加粗；
- 至少包含一个代码块；
- 至少包含一个列表；
- 长度以能完整表达一个小主题为准。

---

### Exercise 3 — README

独立写一份小型 README，至少包含：

- 项目 / 练习名称；
- 用途；
- 如何使用；
- 文件结构或主要内容；
- 当前状态。

目标：

> 理解 README 是面向未来读者的入口文档，而不是随意笔记。

---

### Exercise 4 — 问题树

选择一个具有多个分支的问题，用 Markdown 表达：

- 主问题；
- 当前阻塞问题；
- 非阻塞分支；
- 待处理问题；
- 已解决问题。

目标：

> 将 Markdown 与 AI Learning Anchor 中的问题树原则结合。

---

### Exercise 5 — 表格与链接

创建一份简短技术说明，至少包含：

- 一个表格；
- 一个外部链接；
- 一个相对文档链接；
- 一个代码块。

并解释：

> 为什么这里适合使用表格，而不是列表。

---

### Exercise 6 — 文档重构

由 ChatGPT 提供一份：

- 标题层级混乱；
- 大量加粗；
- 列表结构不清；
- 代码与正文混杂；
- 信息重复；

的低质量 Markdown 文档。

学习者独立重构。

完成后对比：

- 原文问题；
- 修改方案；
- 修改后的信息结构。

---

## 8. 综合作业

### M0 Final Assignment — 技术说明文档

在不直接照抄模板的情况下，独立完成一份新的 Markdown 技术说明文档。

文档必须包含：

- 明确标题；
- 合理的二级 / 三级标题；
- 普通正文；
- 列表；
- 行内代码；
- fenced code block；
- 引用；
- 表格；
- 链接；
- 至少一个相对链接或明确说明为什么当前文档无法合理使用相对链接；
- 清晰的结论或下一步。

主题应由 ChatGPT 在考核时给出，且不能完全复制前面练习。

---

## 9. Review 标准

ChatGPT Review 时重点检查：

### 9.1 正确性

- Markdown 语法是否正确；
- 代码块是否完整；
- 链接格式是否合理；
- 表格是否正常。

### 9.2 结构

- 标题是否表达真实层级；
- 是否存在无意义跳级；
- 列表是否承担了适合的内容；
- 信息是否有清晰入口和收尾。

### 9.3 可读性

- 是否有过长段落；
- 是否过度加粗；
- 是否滥用表格；
- 是否存在可以压缩的重复信息。

### 9.4 技术表达

- 代码与解释是否区分；
- 技术名词是否清楚；
- 文档是否能被一个不了解上下文的人读懂。

### 9.5 AI 可读性

初步检查：

- 结构是否稳定；
- 层级是否明确；
- 事实与说明是否容易区分；
- 是否减少模糊代词和不明确指代。

---

## 10. 完成判据

M0 完成时，学习者应能够：

- 独立创建和编辑 `.md`；
- 熟练使用最常见 Markdown 语法；
- 不依赖模板组织一份短技术文档；
- 用标题和列表表达层级；
- 正确插入代码块、引用、表格和链接；
- 看懂基础 Markdown diff；
- 重构一份低质量技术文档；
- 使用 Markdown 表达一个简单问题树；
- 完成 M0 Final Assignment；
- 能解释为什么某种结构比另一种结构更合适。

不要求：

- 所有语法细节完全记忆；
- 掌握复杂 HTML；
- 掌握高级 Mermaid；
- 成为专业技术写作者。

---

## 11. 收尾要求

完成 M0 后，应进行一次简短复盘：

1. 哪些 Markdown 语法已经自然掌握；
2. 哪些仍需查阅；
3. 结构化写作中最常出现的问题；
4. 是否能在 ProjectVox / AI Learning Project 中独立维护 `.md`；
5. 是否满足进入 M1 的完成判据。

若满足，则 M0 收尾，不继续扩展。

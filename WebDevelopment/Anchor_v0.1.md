# Web Design and Production Learning Project — Anchor v0.1

> 状态：Initial Anchor  
> 版本：v0.1  
> 性质：课程级长期锚点  
> 适用教材：《HTML5+CSS3 网页设计与制作（第2版）》  
> 作用：定义本课程的学习目标、掌握深度、教学原则、教材与现代 Web 实践的边界，以及后续 Roadmap / 教学聊天的职责。  
> 本文件不承担逐节讲义、每日作业或具体考试答案。

---

## 1. 项目定位

本项目服务于本学期“网页设计与制作”专业课。

目标不是只把教材从头到尾看完，也不是在一个学期内直接培养成完整的前端工程师，而是同时建立两条互相配合的主线：

1. **课程主线**：理解教材中的 HTML5、CSS3、基础 JavaScript、Canvas、Web Storage 与网页项目制作内容，能够完成课堂练习、作业、阶段案例和考试要求。
2. **能力主线**：建立可以迁移到后续 Web 开发学习中的真实基础，尤其是 HTML 结构、CSS 选择与层叠、盒模型、布局、表单、调试和独立完成静态网页的能力。

本项目默认把教材视为本学期课程的重要内容来源，但不把教材中的所有技术都视为现代前端开发的最佳实践。

---

## 2. 本课程实际需要学到什么程度

本课程整体定位为：

> **Web 前端入门 + HTML/CSS 主体训练 + 少量 JavaScript/浏览器能力体验 + 综合静态网页实践**

不要求在本课程内达到：

- 完整 JavaScript 编程能力；
- React / Vue 等框架开发能力；
- Node.js 后端开发；
- 完整工程化工具链；
- 复杂网络协议；
- 大型前端项目架构。

但 HTML 与 CSS 基础必须真正掌握，而不能停留在“照着书能抄出来”。

### 2.1 掌握深度分级

后续教学统一使用以下四级：

#### L0 — 见过即可

知道它是什么，看到代码能大致识别；暂不要求独立写出。

#### L1 — 理解

能用自己的话解释用途、基本规则和典型场景；可以在资料帮助下使用。

#### L2 — 能独立使用

不依赖完整范例，能独立写出常见用法，并处理一般错误。

#### L3 — 能解释、调试和迁移

不仅能写，还能解释为什么这样写；遇到常见异常能定位原因；能把知识迁移到新页面或新要求。

### 2.2 各章目标深度

| 教材章节 | 主题 | 课程目标深度 | 备注 |
|---|---|---:|---|
| 第1章 | 网页与开发环境概述 | L1–L2 | 理解网页、HTML/CSS/JS 分工，会使用 VS Code 与浏览器 |
| 第2章 | HTML5 基础 | **L3** | 核心基础，必须独立写页面结构 |
| 第3章 | CSS3 核心基础 | **L3** | 样式规则、引入方式、基础选择器、文本样式必须扎实 |
| 第4章 | 其他选择器 | L2–L3 | 常用关系/属性/伪类选择器重点掌握，少见写法可查 |
| 第5章 | 盒子模型 | **L3** | 全课程最重要内容之一，必须能调试尺寸与间距 |
| 第6章 | 列表和超链接 | **L3** | 常见网页结构基础 |
| 第7章 | 表格和表单 | L2–L3 | 表单尤其重要，应能独立完成常见控件与基本样式 |
| 第8章 | DIV+CSS 布局 | **L3（课程线）** | 布局思想必须掌握；float 属课程重点，但现代实战中不是主要布局方案 |
| 第9章 | 多媒体嵌入 | L2 | 会正确嵌入并理解格式/兼容性即可 |
| 第10章 | 过渡、变形和动画 | L2 | 会制作常见效果，理解 transition / transform / animation 区别 |
| 第11章 | 绘图和数据存储 | L1–L2 | 这是体验性入口，不把它等同于完整 JavaScript 课程 |
| 第12章 | 企业网站实践 | **L3** | 综合检验：能从结构规划到页面实现完成一个小型网站 |

## 3. 教材内容的优先级判断

### 3.1 必须真正掌握

以下内容是课程成绩与后续 Web 学习都高度依赖的基础：

- HTML 基本文档结构；
- 常见文本、图像、链接、列表、表格、表单标签；
- 标签嵌套与父子/兄弟关系；
- CSS 规则结构；
- CSS 引入方式；
- 元素、类、ID 等基础选择器；
- 层叠、继承、优先级；
- 文本与字体样式；
- 盒模型；
- width / height；
- margin / padding / border；
- display 与常见元素类型；
- position / z-index；
- overflow；
- 常见页面结构与命名；
- 基础表单；
- 浏览器中查看、运行和定位样式问题。

### 3.2 课程中要会，但不应过度投入背诵

- 大量结构化伪类的具体组合；
- `list-style-*` 的所有细节；
- `border-image`；
- 多背景图像的复杂写法；
- 大量 transition / animation 子属性的机械记忆；
- Canvas 的大量绘图 API；
- Cookie / Web Storage 的细节语法。

原则：

> **理解规则 + 能完成典型题 + 知道如何查资料**，优于逐条死背冷门属性。

### 3.3 教材中的“历史性重点”

第8章中的 float 布局需要认真学习，因为它属于教材体系和课程考核范围，也有助于理解普通文档流、浮动和清除等概念。

但必须明确：

> **现代网页主布局通常更常使用 Flexbox 和 Grid。**

因此：

- 对 float：课程上达到 L3，理解其行为和典型问题；
- 对真实开发：不把 float 当成未来主要布局工具。

## 5. 学习原则

### 5.1 HTML/CSS 以“会写 + 会解释 + 会调试”为完成标准

学习者不能只做到：

> 看懂老师代码 / 照抄例子 / 运行成功。

核心内容必须逐步达到：

- 能从空白文件开始写；
- 能预测浏览器大致表现；
- 能解释关键标签和属性为什么存在；
- 页面效果异常时能定位 HTML 结构还是 CSS 规则的问题；
- 能修改需求而不是推倒重抄。

### 5.2 不要求死记全部标签和属性

需要形成：

> 常用内容进入长期记忆，低频内容知道存在并会查。

尤其不要把大量低频 CSS 属性名背诵当作学习成果。

### 5.3 代码练习必须由学习者亲自完成核心部分

首次学习核心知识时，优先让学习者亲自：

- 新建 HTML / CSS 文件；
- 输入结构；
- 写选择器；
- 修改样式；
- 观察效果；
- 制造并修复错误。

AI 可以：

- 解释；
- 出题；
- Review；
- 提示；
- 提供局部示例；
- 在学习者完成后给参考实现。

不应默认直接替学习者生成整份作业。

### 5.4 先预测，再运行

对于 HTML/CSS 的大量知识点，优先使用：

> 看代码 → 预测页面结果 → 实际运行 → 比较 → 解释差异

这比单纯阅读规则更容易建立浏览器渲染心智模型。

### 5.5 教材线与现代实践线必须明确区分

教学中若出现教材中的旧式或不再主流做法，应明确标记：

- **课程/考试需要掌握**
- **现代开发中仍常用**
- **现代开发中主要用于兼容或特殊场景**
- **了解即可**

不能因为教材较旧就直接跳过考试内容，也不能把教材写法误教成现代唯一正确做法。

## 6. 教学模式

### 6.1 概念教学

适用于首次接触：

- HTML 文档结构；
- 标签关系；
- CSS 选择器；
- 层叠与优先级；
- 盒模型；
- 文档流；
- 浮动与定位；
- 表单；
- 动画基础。

流程：

> 概念 → 极小示例 → 预测题 → 自己写 → 浏览器验证 → Review

### 6.2 练习模式

适用于语法已经讲过的内容。

优先使用：

- 填空；
- 找错；
- 预测结果；
- 根据效果写代码；
- 修改已有页面；
- 小型页面复刻。

### 6.3 项目模式

进入综合阶段后：

> 需求 → 页面结构 → HTML → CSS → 浏览器调试 → Review → 修正

AI 不应一次性替学习者完成完整项目。

## 7. 考试与真实能力的双轨管理

若老师明确给出：

- 考试范围；
- 题型；
- PPT；
- 课堂重点；
- 作业要求；
- 特殊写法；
- 评分规范；

应把这些作为“课程考核线”单独记录。

出现以下情况时，应明确指出差异：

> 教材/老师要求怎么写  
> vs  
> 现代实际开发通常怎么写

考试复习时优先满足课程要求；能力训练时再补充现代做法。

## 8. 掌握判据

一个知识点不以“讲过”作为掌握。

核心知识原则上应满足多数：

- 能用自己的话解释；
- 能看懂基本代码；
- 能预测常见效果；
- 能独立写出；
- 能发现典型错误；
- 能修改已有代码；
- 能组合进新页面；
- 能说出常见适用场景；
- 能区分它与相近概念。

## 10. 权威来源层级

同一知识出现冲突时，按任务类型处理。

### 对课程成绩 / 考试

优先级原则：

> 老师明确要求 / 评分规范  
> → 课堂 PPT / 课堂示例  
> → 本学期指定教材  
> → 现代 Web 标准与补充资料

若老师要求与现代最佳实践不同，应明确告诉学习者：

> “课程中按老师要求作答；实际开发中另有更常见做法。”

### 对真实能力培养

优先级原则：

> 当前 Web 标准与浏览器实际行为  
> → 现代工程实践  
> → 教材

不得为了迎合旧教材而把过时内容描述为现代主流。

## 12. Anchor 升级规则

以下情况可以升级 Anchor：

- 老师公布与教材明显不同的教学目标；
- 考试/作业要求表明课程深度发生明显变化；
- 本学期实际教学加入 Flexbox、Grid、JavaScript 等重要新内容；
- 教材不是课程主要依据；
- 学习目标从“课程基础”升级为系统前端开发。

普通单次作业、课堂例子和小范围章节调整不升级 Anchor。

# M1 — 研究问题与研究设计

建议时间：第 2 周

## 核心问题

不是“怎么采访用户”，而是：

> 我究竟想知道什么？

## 内容

### 1.1 产品问题 vs 研究问题

例：

产品问题：
“蓝图系统不好用。”

研究问题：
“玩家在选择与放置蓝图时出现错误的主要原因是什么？”

### 1.2 假设

- 显式假设
- 隐含假设
- 如何避免先有结论再找证据

### 1.3 用户范围

- 目标用户
- 极端用户
- 新手
- 熟练用户
- 非用户

### 1.4 方法选择

什么时候适合：

- 访谈
- 观察
- 问卷
- 日志研究
- 可用性测试
- 数据分析

### 1.5 研究伦理

- 知情
- 隐私
- 匿名
- 敏感信息
- 诱导
- 研究者权力

## 作业

写一个完整 Research Plan：

- 背景
- 研究目标
- 研究问题
- 目标用户
- 方法
- 样本
- 时间
- 风险
- 输出

# M2 — 定性用户研究

建议时间：第 3～4 周

## 2.1 用户访谈

学习：

- 开放式问题
- 封闭式问题
- 追问
- 5 Whys 的边界
- 避免诱导
- 避免假设性提问
- 避免让用户预测自己的未来行为

坏问题：

“你是不是觉得这个功能很难用？”

更好的问题：

“上一次你使用这个功能时发生了什么？”

## 2.2 情境访谈

区别：

“你平时怎么用？”

与

“你现在实际操作一次给我看。”

## 2.3 观察法

关注：

- 行为
- 停顿
- 错误
- 绕路
- 自我修正
- 环境
- 工具
- 人与人的协作

## 2.4 访谈编码基础

原始话语
→ 观察
→ 初级编码
→ 主题
→ 洞察

## 实践

至少完成 3 次真实访谈。

建议每次 20～40 分钟。

## 输出

- Interview Guide
- 原始记录
- 编码表
- 第一版研究发现

# M3 — 定量研究与需求判断

建议时间：第 5 周

本阶段不追求统计学专业深度。

## 3.1 问卷

学习：

- 题目设计
- 李克特量表
- 双重问题
- 诱导性问题
- 顺序效应
- 样本偏差
- 自选择偏差

## 3.2 定性与定量的关系

定量不是“比定性科学”。

关键是问题类型不同。

## 3.3 Kano

理解：

- Basic
- Performance
- Excitement

以及 Kano 的局限。

## 3.4 行为数据

了解：

- 点击
- 完成率
- 错误率
- 任务时间
- 留存
- 转化

但避免把指标直接等同于用户体验。

## 作业

设计一份 10～15 题问卷。

# M4 — 从资料到用户模型

建议时间：第 6 周

## 4.1 Affinity Mapping

将零散发现聚类。

## 4.2 Persona

学习：

Persona 应来源于研究模式，而不是“编一个叫小明的用户”。

## 4.3 Empathy Map

理解其用途和局限。

## 4.4 Journey Map

结构：

阶段
→ 行为
→ 想法
→ 情绪
→ 痛点
→ 机会点

## 4.5 Jobs to Be Done 基础

关注用户为什么“雇佣”某个产品完成任务。

## 输出

- Affinity Map
- Persona
- Journey Map
- 需求列表

## 第一阶段 Review

要求回答：

“我的结论中，哪些来自证据，哪些仍然只是推测？”

# M6 — 认知心理与人的限制

建议时间：第 9 周

这是 HCI 最重要的理论阶段之一。

## 6.1 感知

- 视觉搜索
- 对比
- Gestalt 基础
- 空间组织

## 6.2 注意

- 选择性注意
- 分心
- 注意竞争
- 注意切换

## 6.3 记忆

- Working Memory
- Long-Term Memory
- Recognition vs Recall

## 6.4 Cognitive Load

区分：

- 任务本身复杂
- 界面造成的额外复杂

## 6.5 Mental Model

用户认为系统“是怎么工作的”。

系统真实模型与用户心理模型可能完全不同。

## 6.6 学习与熟练化

- 新手
- 中级用户
- 专家

同一个界面不一定适合所有阶段。

## 作业

分析一个“第一次很难学、熟练以后效率很高”的系统。

# M7 — HCI 模型、规律与任务分析

建议时间：第 10 周

## 7.1 Norman Action Cycle

Goal
→ Intention
→ Action specification
→ Execution
→ Perception
→ Interpretation
→ Evaluation

理解：

- Gulf of Execution
- Gulf of Evaluation

## 7.2 Fitts's Law

理解目标距离、目标尺寸与操作时间的关系。

应用：

- 按钮
- 菜单
- 屏幕边缘
- FPS / RTS / 建造游戏目标选择

## 7.3 Hick-Hyman Law

选择数量 / 复杂度与决策时间的关系。

注意：

“选项越少越好”是错误简化。

## 7.4 Steering Law

路径约束下的指针移动。

## 7.5 GOMS / KLM

达到“看懂 + 做简单估算”的程度。

## 7.6 Task Analysis

把复杂任务拆成：

Goal
→ Subgoal
→ Task
→ Action

## ProjectVox 可选练习

拆解：

“玩家放置一个复杂蓝图”

从意图到最终确认的完整行动链。

# M8 — 可用性测试与评估

建议时间：第 11～12 周

## 8.1 Usability

重点维度：

- Effectiveness
- Efficiency
- Learnability
- Errors
- Satisfaction

## 8.2 Usability Testing

流程：

目标
→ 任务
→ 测试用户
→ 主持
→ 观察
→ 指标
→ 发现问题
→ 严重性

## 8.3 Think Aloud

学习：

- 优点
- 干扰
- 主持人应该什么时候说话

## 8.4 Heuristic Evaluation

重点学习 Nielsen 常用启发式原则，并理解：

启发式评估 ≠ 用户测试。

## 8.5 指标

- Task Success
- Time on Task
- Error Rate
- Assistance
- SUS 基础

## 实践

至少完成 3 名真实测试者。

# M9 — 新型人机交互

建议时间：第 13～14 周

本阶段对应学校《人机交互技术》中较强的技术扩展部分。

## 9.1 Touch

- 手指不是鼠标
- 遮挡
- 触控目标
- 手势记忆

## 9.2 Gesture

- 可发现性
- 误触
- Midas Touch Problem

## 9.3 Voice UI

- 无屏 / 有屏
- Recognition Error
- Turn Taking
- Feedback

## 9.4 VR / AR / MR

核心问题：

- 空间定位
- 深度
- 晕动
- 视野
- 控制器
- 手部追踪
- Locomotion
- Spatial UI

## 9.5 Motion Capture

理解：

- Tracking
- Pose
- Calibration
- Occlusion

## 9.6 Haptics

触觉反馈能够传达什么信息。

## 9.7 Eye Tracking

了解：

- Fixation
- Saccade
- Gaze Interaction

## 9.8 BCI

仅建立基础认识：

- 信号
- 意图识别
- 噪声
- 高带宽幻想与现实限制

## 9.9 Multimodal Interaction

视觉 + 听觉 + 手势 + 语音 + 触觉。

## 9.10 Human-AI Interaction

扩展至当前数字产品：

- 不确定性
- 可控性
- 可解释性
- 信任
- Automation Bias
- Prompt / Conversation
- AI 错误恢复

# M10 — 综合项目

建议时间：第 15～16 周

## 项目任务

选一个真实交互系统，完成：

### Part A — Research

- 背景
- 研究问题
- 用户范围
- 方法
- 访谈
- 数据分析
- 用户模型

### Part B — Interaction Analysis

使用至少 3 个理论：

例如：

- Mental Model
- Cognitive Load
- Fitts's Law
- Hick-Hyman Law
- Feedback
- Mapping
- Error
- Norman Action Cycle

### Part C — Design

提出新的：

- User Flow
- Interaction Model
- Wireframe / Prototype

### Part D — Evaluation

完成：

- Usability Test
- 结果分析
- 修改

### Part E — Reflection

回答：

1. 哪些最初假设被推翻？
2. 哪些结论证据最强？
3. 哪些证据不足？
4. 下一轮研究应该做什么？

建议互动模式：

知识讲解
→ 1 个现实案例
→ 极短判断题
→ 错误解释
→ 小练习
→ 项目迁移
→ Module Review

每学习 2～3 个概念，就插入一次主动判断或应用。

# 最终能力检查

如果学期结束时面对一个陌生软件，你能够：

1. 找到目标用户；
2. 把模糊问题变成研究问题；
3. 选择合适研究方法；
4. 进行基本访谈与观察；
5. 从资料中找出规律；
6. 区分需求与个人意见；
7. 建模用户任务；
8. 分析人的认知限制；
9. 找到交互中的反馈、映射、模式与错误问题；
10. 用 HCI 模型辅助判断；
11. 做基本原型；
12. 设计一次可用性测试；
13. 根据测试证据修改方案；
14. 分析 VR、AR、语音、手势、AI 等新型交互的适用性；

则可视为完成本 Roadmap。

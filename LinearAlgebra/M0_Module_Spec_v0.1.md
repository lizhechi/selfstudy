# M0 Module Spec：前置基础、数学语言与线性系统初步 v0.1

> 文件名：`M0_Module_Spec_v0.1.md`  
> 上位文件：`Anchor_v0.1.md`、`Roadmap_v0.1.md`  
> 阶段性质：第一个实际能力阶段；入口诊断不单独构成阶段。

## 1. 阶段目的、边界与入口诊断

M0 的目的不是提前讲完整的行列式或矩阵章节，而是建立后续学习所需的最低可靠能力：读懂常见符号、稳定完成必要代数操作、理解并求解小型线性方程组，以及主动验证结果。

本阶段不假定学习者已经学过线性代数。开始时进行一次短诊断，覆盖：

- 正负号、分数与括号运算；
- 移项、合并同类项和简单代入；
- 下标、幂、求和符号等基础阅读；
- 一元方程及简单二元一次方程组；
- 对“式、方程、解、系数”等词的直观理解。

诊断只用于决定从哪里开始和练习多少，不计为 Final Review，也不因低分阻止进入教学。若某项完全陌生，先提供完成当前阶段所需的最小补救。

M0 只预览矩阵、向量和行列式分别是哪类对象以及为何会出现；它们的正式定义、性质与系统计算属于后续阶段。

## 2. 学习成果—活动—证据

| 编号 | 阶段学习成果 | 主要活动 | 必须留下的证据 |
|---|---|---|---|
| O1 | 区分数、变量、系数、代数式、方程、方程组，并初步区分矩阵、向量与行列式 | 对照例子分类，用自己的话说明对象身份 | 对一组混合对象正确分类，并修正至少一个容易混淆的反例 |
| O2 | 正确读取下标、幂、括号、分数、`Σ` 等后续会遇到的符号 | 逐项朗读、改写、从文字还原符号 | 把若干符号表达式准确改写成文字，并从文字写回表达式 |
| O3 | 稳定进行后续计算需要的代数变形 | 分步运算、错误定位、逆向检查 | 完成包含负号、分数、括号和移项的混合题，并指出错误题的首个错误步骤 |
| O4 | 用消元或代入求解二元线性方程组，并判断和验证结果 | 手算、代回、比较不同方程关系 | 独立求解并验证唯一解问题；直观识别无解与无穷多解的简单情形 |
| O5 | 把一个简单情境转写为线性方程组，并解释表示、求解和验证之间的关系 | 建模、小型变式、口头或书面解释 | 完成一项从情境到方程组再到结论的闭环任务，并说明为何需要更紧凑的表示工具 |

## 3. 必学内容、关键辨析与推荐顺序

### A. 数学对象与符号

- 数、未知量、系数、常数项；
- 代数式不等于方程，方程不等于它的解；
- 下标表示位置或编号，幂表示重复相乘，两者不能混读；
- `Σ` 表示按规则求和；只要求能展开和还原小规模例子；
- 行、列、坐标的基本方向；向量、矩阵、行列式只做身份预览。

### B. 必要代数操作

- 运算顺序、括号展开、负号分配；
- 分数约分、通分和含分数等式的处理；
- 合并同类项、移项、代入与等价变形；
- 用逆运算、代回和数量级检查结果。

### C. 线性方程与方程组

- “线性”的初步含义：未知量只以一次方式出现，不相乘、不作为分母；
- 一个有序数对何时是方程组的解；
- 代入法和消元法的目的与等价操作；
- 唯一解、无解、无穷多解的直观差异；
- 两条直线交点作为辅助直觉，但不把画图当作精确求解的替代。

### D. 表示桥接

- 从方程组中识别系数、未知量和常数项；
- 把系数按行列排列，理解“结构化记录”为什么比反复抄写更可靠；
- 初步知道后续将用矩阵表示、用行列式提取某些数值信息，但不提前套用未学规则。

推荐顺序为 A → B → C → D。诊断若证明某部分已经稳定，可缩短练习，但仍需在后续证据中确认能够迁移。

## 4. 形成性练习

### 练习组 1：对象分类与符号双向翻译

对混合示例进行分类；解释 `a_2` 与 `a^2`、`a_{ij}` 中两个下标、简短求和式的含义；再把自然语言写成符号。作用是发现“看似会算但读错对象”的问题。

### 练习组 2：运算与首错定位

完成负号、分数、括号、移项混合题；同时检查一份带错误的解答，只指出第一个导致后续失效的步骤并修正。作用是建立可复用的调试习惯，而不是追求题量。

### 练习组 3：方程组求解与验证

分别处理唯一解、明显矛盾和两个方程等价的二元方程组；至少一次使用代入法、一次使用消元法，并通过代回验证。作用是把“计算结果”与“解的结构”区分开。

### 练习组 4：情境建模与轻量变式

从价格组合、资源分配或两种成分混合等简单情境建立方程组；改变一个条件，判断解的情况是否可能变化。作用是证明学习者能从题目表面迁移到相同结构。

各组只练到相应证据稳定出现。已经稳定正确的项目不机械加量；错误则进入最小补救后再次取证。

## 5. Final Assignment

学习者独立完成一项“M0 表示—求解—验证”整合任务，核心作答不得由 AI 代写。任务必须包含：

1. 从一个未见过但不复杂的双变量情境中定义未知量并建立两个线性方程；
2. 标出系数、未知量和常数项，并把系数按行列写成紧凑排列；
3. 选择代入或消元求解，保留足以检查的步骤；
4. 把结果代回原方程，并用一句话解释它在原情境中的含义；
5. 分析一个经修改的条件为何导致唯一解、无解或无穷多解中的一种；
6. 简述代数式、方程、方程组、矩阵和行列式的主要身份差异，其中矩阵和行列式只要求阶段边界内的初步辨认。

允许学习者在收到反馈后进行一次针对性修订；修订必须说明改了什么以及原错误属于哪一类。

## 6. Final Review 与完成判据

Final Review 汇总形成性证据和 Final Assignment，先给出明确的“通过／未通过”，再说明依据。

M0 通过需要同时满足：

- O1、O2：关键对象与符号不再发生身份性混淆；普通题正确率达到约 80%，且被指出后的关键错误能够独立修正；
- O3：Final Assignment 中不存在未解决的负号、分数、括号或等价变形错误；
- O4：能独立求解并代回验证一个唯一解方程组，同时正确解释至少一个无解或无穷多解的简单例子；
- O5：能完成情境—方程组—求解—原情境解释的闭环，并说清表示工具的作用；
- 能指出自己当前最容易发生的一类错误和对应检查动作。

不能仅凭完成题数、聊天轮数、入口诊断得分或 AI 提示后的最终答案宣布通过。若核心步骤仍依赖逐步提示，相关成果尚未形成独立证据。

## 7. 未通过时的最小补救路径

| 未通过项目 | 最小补救 | 复查范围 |
|---|---|---|
| 对象或符号身份混淆 | 做一组“分类＋反例＋文字/符号互译”微练习 | 只复查 O1、O2 及其直接依赖 |
| 负号、分数或等价变形不稳 | 针对首错类型完成少量分步题，并使用逆向检查 | 只复查 O3 和 Final Assignment 中受影响步骤 |
| 会算但不会验证或解释解的情况 | 对一个唯一解和一个非唯一情形执行“求解—代回—解释” | 只复查 O4 |
| 不会从情境建立方程 | 使用“未知量—关系—方程—单位”脚手架完成一个新情境 | 只复查 O5 及必要的 O4 |
| 过度依赖提示 | 隔一小段时间完成同结构新题，AI 只提供题目与最终反馈 | 复查缺少独立证据的成果 |

补救不重做已稳定通过的部分；复查失败项及其直接依赖即可。

## 8. Progress Snapshot、Completion Summary 与交接

若 M0 跨聊天继续，只维护一个 `M0_Progress_Snapshot_v0.1.md`。它至少记录：

- 阶段编号与名称、最后更新时间；
- 所依据的 `Anchor_v0.1.md`、`Roadmap_v0.1.md`、`M0_Module_Spec_v0.1.md`、`M0_Startup_Prompt_v0.1.md`；
- 已完成内容与对应证据；
- 当前任务及完成到哪一步；
- 尚存错误、薄弱点和已采用的检查动作；
- 关键决定、Parking Lot、迁移说明（如有）；
- 精确下一步及恢复所需文件。

依据文件升级时，保留未受影响的证据，只复查新规则实际影响的部分，并在同一 Snapshot 中更新依据版本和迁移说明。Snapshot 不能代替 Final Review。

M0 通过后生成 `M0_Completion_Summary_v0.1.md`，记录通过证据、仍需间隔复现的薄弱点、未决项和进入 M1 的准备度；随后停止把 M0 Snapshot 作为活动输入。只有完成该记录后，才询问是否根据实际结果生成 M1 Module Spec 与 Startup Prompt。

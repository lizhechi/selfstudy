# C# 面向对象程序设计学习项目 Anchor v0.3

> 文件名：`Anchor_v0.3.md`  
> 文档性质：项目级长期规范。  
> 状态：v0.3；阶段—聊天连续性规则的主权威，并补充规范升级时的最小状态迁移。  
> 项目事实权威顺序：本 Anchor → Roadmap → 当前阶段 Module Spec。

## 1. 项目定位与建立目的

本项目是一个**课程 / 教材对齐优先，实际编程能力次优先**的长期学习项目。它以《C#面向对象程序设计教程（微课视频版）》为主要范围参考，衔接学校 C# 课程，并把已有的少量 C++ 基础迁移为可用于 C# 与 .NET 应用开发的知识。

项目不以逐页读完教材或记住全部语法为目标，而以形成以下闭环为目标：能理解程序结构，能亲自编写与运行代码，能定位常见错误，能解释关键设计选择，并能完成带数据与图形界面的综合小型应用。

教材是本项目的重要输入，但不等同于 C#、.NET 或软件工程领域的全部内容。

## 2. 范围、非目标与深度边界

项目范围包括：

- C#、.NET、开发工具、项目文件与程序执行链路；
- 数据类型、表达式、控制流、数组、字符串与函数；
- 类、对象、封装、继承、多态、接口、委托、事件与异常；
- 泛型、集合、比较、类型转换及教材涉及的进阶语言特性；
- LINQ、文件、流、序列化与数据库访问；
- WPF、XAML、布局、控件、数据绑定、命令与基础 MVVM；
- 一个整合需求、对象模型、数据持久化与界面的综合应用。

深度以“能够独立完成课程任务与中小型练习，并能继续自学”为界。项目会补充必要的现代实践，但不扩展为完整的 .NET 职业开发路线。

当前非目标包括：

- 穷尽 C# 语言规范、.NET API 或 CLR 实现细节；
- 系统学习 ASP.NET Core、云服务、移动开发、Unity、MAUI 或跨平台 UI；
- 深入并发、网络协议、性能工程、企业级架构与部署运维；
- 把教材中的每个案例原样复刻一遍；
- 用 AI 生成完整答案来替代学习者的核心编写、调试与判断。

## 3. 来源权威与冲突处理

外部学习来源按用途处理：

1. 教师明确要求、作业说明与考试口径决定课程中“需要怎样作答或提交”；
2. 教材正文、目录和配套微课决定课程范围参考与教材术语；
3. Microsoft 官方文档用于校准当前 .NET、C#、WPF 与数据访问实践；
4. 本项目文件只负责组织目标、顺序、活动与证据，不替代上述原始来源。

若三者存在差异，必须分别标注为**课程要求**、**教材表述**或**现代实践**，说明各自适用场景，不静默用一方覆盖另一方。

当前已确认的校准结论：

- 教材并列介绍 `.NET Framework` 与 `.NET Core`；现代官方术语中，原 `.NET Core` 路线已统一称为 `.NET`，是新开发的主要实现，而 `.NET Framework` 仍用于既有 Windows 应用。若课程指定目标框架，课程任务仍按指定框架完成。
- WPF 仍可运行在现代 .NET 上，但属于 Windows 桌面 UI 技术；本项目学习 WPF 是因为教材与课程范围需要，不把它泛化为跨平台界面方案。

参考：Microsoft Learn 的 [.NET implementations](https://learn.microsoft.com/dotnet/fundamentals/implementations)、[Get started with .NET Framework](https://learn.microsoft.com/dotnet/framework/get-started/) 与 [WPF overview](https://learn.microsoft.com/dotnet/desktop/wpf/overview/)。

对图片识别结果使用三级状态：清晰可读内容视为**可确认**；由目录结构得出的范围关系视为**合理推断**；版次、出版年份、教师实际取舍等未显示信息视为**待核实**。

## 4. 最终能力与项目级完成定义

项目完成时，学习者应能：

1. 区分 C#、.NET、运行时、SDK、IDE、解决方案、项目、源码与构建产物，并说明程序从源码到运行的大致链路；
2. 使用 C# 的基础语法、控制流、集合与函数，把问题拆成可读、可调试的程序；
3. 使用类、封装、继承、组合、接口与多态建立对象模型，并说明选择理由；
4. 使用异常、泛型、委托、事件、LINQ、文件与数据访问能力处理常见应用需求；
5. 使用 WPF、XAML、数据绑定与命令制作基础桌面界面，并维持最低限度的职责分离；
6. 借助调试器、错误信息和最小复现定位编译错误、运行错误与逻辑错误；
7. 对 C++ 与 C# 中外形相近但语义不同的概念主动划清边界，而不是只靠语法相似性迁移。

项目级完成证据是一项可运行的综合应用及其简短说明。该应用至少应包含明确需求、对象模型、集合或查询、可靠的输入处理、持久化数据、WPF 界面和可复现的运行步骤；学习者能够现场修改一个小需求、修复一个缺陷，并解释主要设计取舍。各阶段还须留有 Completion Summary，证明能力不是只在最终作品中偶然出现。

## 5. 稳定约束

- 当前实践环境以 Windows 与 Visual Studio 2022 为主；实际目标框架与项目模板在 M0 记录，不预先猜定。
- M0～M9 是能力与验收阶段，不是预设的聊天数量；任一阶段可以跨多个聊天，聊天切换不改变阶段编号或完成门槛。为便于识别，聊天标题可以标记为“M3 第 1 个聊天”“M3 第 2 个聊天”等；该编号只表示同一阶段内的聊天顺序，不构成 `M3.1`、`M3.2` 等正式阶段，也不产生新的完成判据。
- 到达自然检查点、准备更换聊天，或继续累积上下文会降低恢复可靠性时，应维护当前阶段唯一的滚动 Progress Snapshot。续接聊天读取本 Anchor、Roadmap、当前 Module Spec、当前 Startup Prompt 与最新 Snapshot，从其中记录的下一步继续，跳过已有充分证据的内容；只有阶段通过 Final Review 后才生成正式 Completion Summary。
- 若上述依据文件在阶段中途升级，旧版可取得时先比较新旧规则并保留未受影响的学习证据，只补做或复查受变化影响的部分；旧版无法取得时以当前规则为准，只最小复查无法确认兼容的证据，不臆造差异。随后更新同一 Snapshot 中的依据文件与迁移说明；不得因文件升级默认重做整个阶段，也不得静默沿用已被替代的规则。
- 学习者亲自输入核心代码、运行程序、观察结果并做关键判断；AI 可解释、拆解、提供局部示例、设计练习、检查与反馈。
- 已有 C++ 基础优先作为类比入口，但每次迁移都要区分“共同概念”“C# 特有行为”和“暂不展开内容”。
- 学习证据优先采用可运行程序、调试记录、修改说明与口头或文字解释，不以抄写定义作为主要验收方式。
- 教材案例可用于理解，但阶段交付物应包含变化或迁移，避免只照抄已给答案。

- **待核实**：教师本学期实际讲授范围、作业形式、考试方式与评分重点。
- **待核实**：课程要求的目标框架、控制台项目模板、数据库产品及是否必须沿用教材案例技术。

## 7. 更新规则

只有长期目的、范围、最终能力、来源优先级或稳定约束发生实质变化时才更新本 Anchor。教师进度、当前阶段规范、阶段内进展、阶段完成证据和临时问题分别进入 Roadmap 校准、当前 Module Spec、当前 Progress Snapshot、Completion Summary 或 Parking Lot，不写回 Anchor。
